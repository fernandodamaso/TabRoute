# TabRoute v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build TabRoute v1 as a Chrome-only Manifest V3 extension that deterministically groups tabs, resolves duplicates, preserves persistent group tabs, restores snapshots, and exposes quiet, reversible controls through its popup, settings page, context menus, and shortcuts.

**Architecture:** A WXT service worker converts Chrome events and user commands into reconciliation requests. Pure TypeScript engines calculate rules, duplicates, persistence, and restore intent; only the Tab Action Engine may mutate Chrome. React entrypoints render the popup and settings page, while versioned repositories keep portable configuration in `storage.sync`, machine state in `storage.local`, and restart-scoped intent in `storage.session`.

**Tech Stack:** Node.js 24 LTS, npm 11, TypeScript 6, WXT 0.21, Vite 8, React 19, Zod 4, Vitest 4, Testing Library, Playwright 1.62, ESLint 10, and Prettier 3.

## Global Constraints

- Target Google Chrome 121+ and Manifest V3 only; Chrome 121 is the floor because duplicate ordering uses `tabs.Tab.lastAccessed`. Do not add Firefox, Edge, Safari, or Manifest V2 build paths.
- Never read, classify, mutate, snapshot, or restore Incognito tabs or windows.
- Never add desktop notifications, telemetry, analytics, accounts, remote services, or remotely hosted code.
- Do not add a side panel, command palette, tab search, memory management, group limits, import from existing extensions, or plugin system.
- Use extension-owned UUIDs as durable identity. Chrome `tabId`, `groupId`, and `windowId` are runtime associations only.
- Treat service-worker globals as caches. All recoverable state belongs in the storage area assigned by the design.
- Use `chrome.alarms` for periodic and delayed work; do not depend on JavaScript timers surviving worker termination or on `runtime.onSuspend` firing.
- Only `src/actions/executeActionPlan.ts` and its `ChromeMutationPort` adapter may call Chrome mutation methods.
- Preserve manual tab placement until Chrome restart, except that persistent-tab repair returns a required tab to its assigned group immediately.
- Respect intentionally closed persistent groups until Chrome restart and route their matching tabs to `Other`.
- Reuse acceptable existing tabs before creating restore tabs, and never steal focus during background persistence repair.
- Resolve duplicate survivor order as correct group, then most recently active, then earliest observed in the current browser session; use deterministic initial-inventory order and tab ID only as session-local fallbacks after restart.
- Keep snapshots, activity, Undo, window ownership, and runtime associations out of Chrome Sync.
- Use test-driven development for every behavior change and commit after every task passes its specified gate.
- Use npm and commit `package-lock.json`; do not introduce a second package manager.
- Use Node.js `>=24 <25`. Production dependencies are limited to React, React DOM, and Zod unless the design is amended.

### Chrome API assumptions locked for execution

- Create native groups only with [`chrome.tabs.group()`](https://developer.chrome.com/docs/extensions/reference/api/tabs) and a non-empty tab-ID list. `chrome.tabGroups` updates, queries, and moves existing groups; it does not create an empty group.
- Treat `tabs.Tab.id`, `tabGroups.TabGroup.id`, and `windows.Window.id` as browser-session values. `tabs.Tab.lastAccessed` is the only Chrome-provided recency input; first-observed age belongs to Session state.
- Use [`chrome.tabGroups.move()`](https://developer.chrome.com/docs/extensions/reference/api/tabGroups) for group/window order and restrict both source and destination to normal windows.
- Use [`chrome.storage.session`](https://developer.chrome.com/docs/extensions/reference/api/storage) for one coherent runtime record; it survives worker recreation but clears on extension disable/reload/update and browser restart.
- Use [`chrome.sessions.getRecentlyClosed()` and `restore(sessionId)`](https://developer.chrome.com/docs/extensions/reference/api/sessions) for exact duplicate Undo. Never call `restore()` without the recorded ID.
- Use [`chrome.alarms`](https://developer.chrome.com/docs/extensions/reference/api/alarms) for periodic and trailing checkpoint work, recreate missing alarms on worker wake, and tolerate late delivery.
- Do not use `runtime.onSuspend`; Chrome's [MV3 API migration table](https://developer.chrome.com/docs/extensions/develop/migrate/api-calls) marks it unsupported in extension service workers.
- Declare shortcuts under the top-level [`commands`](https://developer.chrome.com/docs/extensions/reference/api/commands) object. `commands` is not a permission, and exactly four declarations receive suggested keys.
